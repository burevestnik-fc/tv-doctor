# Устройство проекта

ТВ-Доктор — одно Android-приложение на Kotlin с интерфейсом на Jetpack Compose.
Сервера нет: телефон напрямую подключается к телевизору по протоколу ADB через библиотеку
[Kadb](https://github.com/flyfishxu/kadb) и выполняет на нём shell-команды.

## Структура файлов

```
app/src/main/java/ru/tvdoctor/
├── MainActivity.kt          Точка входа. Реализует выгрузку: поделиться, сохранить в Загрузки, файлом, в буфер
├── adb/
│   ├── AdbClient.kt         Подключение, сопряжение, выполнение команд, перезагрузка ТВ
│   └── NetCheck.kt          «Проверить связь» и «Найти ТВ в сети» (mDNS)
├── diag/
│   ├── Models.kt            Модели данных: снимок системы, отчёт о загрузке, приложение, вывод, действие
│   ├── Diagnostics.kt       Сбор данных: снимок, журнал загрузки, приложения, тест памяти, замер запуска
│   ├── Parsers.kt           Разбор вывода команд (meminfo, df, top, ps, logcat, getprop, dumpsys)
│   ├── Analyzer.kt          Правила: данные → выводы, оценка 0–100, история «до/после»
│   ├── KnownApps.kt         Справочник приложений: название, описание, можно ли отключать
│   ├── Maintenance.kt       Обслуживание: TRIM, оптимизация, кэш, фон, большие файлы, прошивка
│   └── Report.kt            Текст выводов и полного отчёта для выгрузки
└── ui/
    ├── MainViewModel.kt     Состояние интерфейса (UiState) и все действия; история и настройки
    ├── Screens.kt           Все экраны и вкладки
    ├── CommandLibrary.kt    Справочник готовых команд терминала
    └── TerminalText.kt      Подготовка команд терминала и очистка вывода; разбор журнала запусков
```

Ресурсы: `res/drawable/ic_launcher.xml` (значок), `res/xml/file_paths.xml` (папки для отправки файлов
через FileProvider). Подпись: `app/debug.keystore` — постоянный ключ, чтобы новые версии
ставились поверх старых.

Разрешения: только `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`.

## Поток данных

```
Экран (Screens.kt)
   │ нажатие кнопки
   ▼
MainViewModel ── runBusy(...) ──► Diagnostics / Maintenance ──► AdbClient.shell(cmd) ──► ТВ
   │                                      │
   │                                      ▼ сырой вывод
   │                                 Parsers → модели (SystemSnapshot, BootReport, AppInfo…)
   ▼
UiState ◄── Analyzer.analyze(...) → List<Finding> → оценка, итог, история
   │
   ▼
Экран перерисовывается
```

1. **Подключение.** `MainViewModel.connect()` → `AdbClient.connect()`. Если порт не ответил,
   `connectViaDiscovery()` ищет через mDNS актуальный порт «Беспроводной отладки» на том же IP.
2. **Сбор.** `collectSnapshot()` → `Diagnostics.snapshot()` выполняет пачку команд и собирает
   `SystemSnapshot`. Сырые ответы сохраняются в `raw` — для полного отчёта.
3. **Анализ.** `refreshFindings()` вызывает `Analyzer.analyze(snapshot, boot, apps, storageTest)`.
   Каждое правило добавляет `Finding` (важность, заголовок, текст, кнопка или список с галочками).
   Затем `enrich()` подписывает пункты с галочками через `KnownApps`.
4. **История.** `recordHistory()` сохраняет ключевые цифры сеанса и строит строки «▲ лучше / ▼ хуже».
5. **Действия.** Кнопка в выводе → `onAction(FixAction)` → нужная функция ViewModel. Отключение
   приложений требует подтверждения (`pendingAction`).

### runBusy

Все операции с ТВ идут через `runBusy(label, cancellable)`: показывает полосу прогресса и текст,
не даёт запустить вторую операцию одновременно, превращает исключения в понятное окно ошибки
(`humanError`), умеет отменяться (`cancelBusy`). Внутри операции `status(text)` обновляет текст.

## AdbClient — связь с ТВ

- **Ключ** хранится в `files/adb_private_key.pem`, поэтому ТВ «запоминает» телефон после «Разрешить — Всегда».
- **Выполнение команды.** Команда отправляется через службу `exec:` (без интерактивной оболочки)
  в обёртке `( команда ) 2>&1; echo __TVD_END_<время>__`. Ответ обрезается по метке.
  Если метки нет — в канал попал «мусор» от прошлой команды: соединение пересоздаётся, команда повторяется.
  Если `exec:` недоступен — используется обычный `shell`.
- **Тайм-аут сокета** — 90 секунд. Поэтому долгие операции (оптимизация приложений) запускаются
  на ТВ в фоне через `setsid`, а приложение опрашивает файл-метку.
- **Мьютекс**: команды выполняются строго по одной.
- **Перезагрузка** — через службу `reboot:`, запасной вариант `svc power reboot`.

## Analyzer — выводы и оценка

- Правила сгруппированы: `analyzeSnapshot`, `analyzeStorage`, `analyzeBoot`, `analyzeApps`.
- Важность: `CRIT` (‼), `WARN` (!), `INFO` (i), `OK` (✓). Сортировка по важности.
- **Оценка:** 100 − 25 × CRIT − 10 × WARN, в пределах 0–100.
- **Нагрузка:** `SystemSnapshot.realLoad = load1 − dStateCount` (без драйверов в состоянии D),
  `cpuBusyPct` — по простою из `top`. «Процессор перегружен» — при занятости ≥ 75%.
- **История** (`historyEntry`, `compare`): загрузка до экрана, реальная нагрузка, свободная ОЗУ,
  свободное место, приложения в автозапуске, мелкая запись, оценка.

## Где что хранится (SharedPreferences `tvdoctor`)

| Ключ | Что |
|---|---|
| `host`, `port` | Последний адрес ТВ |
| `history` | JSON-массив последних 40 сеансов замеров |
| `maint_trim`, `maint_dexopt`, `maint_cache`, `maint_kill` | Когда последний раз выполнялась процедура обслуживания (мс) |

Галочки в выводах и выбор файлов живут в `UiState` (не сохраняются после закрытия приложения).

## Как расширять

### Добавить новую проверку

1. Если нужны новые данные — добавьте поле в `SystemSnapshot` (`Models.kt`) и команду в `Diagnostics.snapshot()`
   через `run("ключ", "команда")`, чтобы ответ попал в сырой отчёт.
2. Если вывод сложный — напишите разборщик в `Parsers.kt`.
3. Добавьте правило в подходящую функцию `Analyzer`: `f += Finding(Severity.WARN, "Заголовок", "Пояснение", FixAction(...))`.
4. Если нужна кнопка — новое значение в `ActionKind` и ветка в `MainViewModel.execute()`.
5. Для списка с галочками передайте `choices = listOf(Choice(pkg, pkg))` и `choiceActions`.

### Добавить команду в справочник терминала

`CommandLibrary.kt` → нужный `LibCategory` →
`LibCmd("Название", "команда", "Описание", changes = true)` (`changes = true` — если команда что-то меняет).

### Добавить приложение в справочник

`KnownApps.kt` → `MAP`: `"пакет" to AppNote("Название", "Что делает", Verdict.BG_ONLY)`.
`Verdict`: `DISABLE_OK` — можно отключить, `BG_ONLY` — только запрет фона, `KEEP` — не трогать.

### Добавить процедуру обслуживания

1. `Maintenance.kt`: константа id, `MaintTask(...)` в `TASKS`, функция с логикой.
2. `MainViewModel`: функция `maintXxx()` через `runBusy`, в конце `markDone(id, итог)`.
3. `Screens.kt` → `MaintTab`: ветка в `when (t.id)` с кнопкой.

## Важные приёмы

- **Строки с переносом.** В Kotlin внутри обычной строки только `\n`, не настоящий перенос — иначе сборка падает (так было в сборке 23).
- **Команды с кавычками и `$`** в Kotlin-строках экранируются: `\$` для переменных оболочки.
- **Списки в LazyColumn.** Состояние, которое должно пережить прокрутку (галочки), хранится в ViewModel, а не в `remember` внутри элемента.
- **Выделение текста.** `SelectionContainer` вокруг `LazyColumn` приводит к вылету — в терминале вывод показывается одним блоком текста.
- **Буфер обмена** не принимает мегабайты — копирование ограничено 400 тыс. символов (`TerminalText.MAX_CLIP_CHARS`).
